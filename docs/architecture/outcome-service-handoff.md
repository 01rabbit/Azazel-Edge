# Offline key provisioning and single-service capture handoff

Tracking: #400. Software implementation and offline tests only. **No production
service/key has been changed by these tests.** A disposable QEMU VM now exercises
real PID1 systemd handoff and OS reboots; see the
[virtual-systemd protocol](outcome-systemd-vm.md). Target-host account/policy/LSM
commissioning and G6 physical-device acceptance remain open.
The [normal-core capture contract](outcome-live-origin.md) remains authoritative;
this layer neither creates provider facts nor fills observation gaps.

The [role confinement profile](outcome-service-confinement.md) adds explicit
new-scope registered capture AppArmor checks and virtual named-account evidence.
The managed drop-in inherits its already verified root identity; it does not
force User/Group or grant privileges. Declared native AppArmor profiles remain
unsupported and are refused; the sealed executable is not weakened to fit policy.

## Supported boundary and exclusion

Only the existing `azazel-edge-core.service` is switched. There is no second
installed enforcer unit, automatic installer activation or observer/AI control
endpoint. Root runs explicit preparation/import/review/apply/restore commands.

Every new normal Rust daemon holds `core-instance.lock` in its **release-state
directory** for its entire lifetime, before release recovery, capture startup,
input or provider work. The root capture launcher acquires that same lock before
signer preparation and passes the descriptor to its core. No PID-file reset,
unlink, timeout takeover or alternate implicit lock exists. Owner/mode/type,
physical protected ancestors, one-link namespace identity and nonblocking
exclusive flock are checked. The descriptor is close-on-exec for provider
commands. Kernel process exit releases the lock; the empty lock file is retained.
Health/version/maintenance one-shots do not start a daemon or claim this lock.

The ordinary unit explicitly names its existing default release-ledger path
and prevents restart on exit 3 (instance/preflight refusal). Other ordinary
restart behavior is unchanged. Both normal and signed daemons using that state
directory exclude each other. A root launching renamed/older/noncooperating
software or intentionally using another state directory is outside this lock
scope; the switch additionally inventories known normal/memfd cores and refuses
unmanaged/duplicate processes. It never kills arbitrary PIDs. Only the one fixed
unit may be stopped/started. Deploy a reviewed guard-capable image before using
this handoff; the safe existing `--health` response advertises the additive
`azazel-edge-core/capture-service/v1` capability without running provider work.
It is software capability metadata, not an admission or healthy-machine claim.

All bundle choices serialize through a root-private global controller lock at
`/run/azazel-edge-core-switch`, independently of the per-core state-directory
lock. Operations cannot race merely by choosing different capture bundles.
No lock grants execution privileges or proves whole-host anti-rollback.

## Public candidates, private import and quarantine

The root operator supplies a protected public v1 trust template with explicit
new scope, distinct capture/witness public keys, three existing distinct role
UIDs and finite budgets. Capture/observer UIDs must be non-root and dedicated,
without AI identity, sudo access, privileged capabilities or key/anchor ACLs.
This tool creates no users, groups, ACLs/capabilities or credentials. Keys must
be generated by the trusted offline operator beforehand; no default/shared key,
key generation, environment-secret fallback or replacement on failure exists.

`input_service prepare` reads only the public template, registered root-owned
ELF and explicit core environment. It needs no destination directory or private
keys, writes nothing and emits `trust_policy`/`registration` candidates. Paths
are rewritten to a **new absent** physical bundle root:

| Path within bundle | Owner/mode/purpose |
| --- | --- |
| root | root `0755` only after complete provisioning; `0700` while partial |
| `trust.json`, `origin.json`, `provisioned.json` | root `0644`, pinned public data/completion receipt |
| `producer/`, `producer/key.raw` | capture UID, `0700` directory / `0600` raw key |
| `witness/`, `witness/key.raw`, `witness/anchors/` | root, private `0700` directories / `0600` raw key |
| `observer/` | observer UID `0700`, existing journal/loss policy |
| `input` | capture UID `0644`, precreated empty bounded signed source |
| `socket/` | root `0755`, existing observer-UID-only witness endpoint |
| `switch/` | root `0700`, reviewed plan/stage receipts; never evidence repair |

`provision` imports two operator-provided root-owned `0600`, single-link,
32-byte raw Ed25519 files, and verifies each public key against the registered
role **before writing**. Private file bytes are never printed, put in arguments,
environment, public receipts or examples. They are `0600` from their first byte;
file/directory syncs and a completion receipt precede successful publication.
New state stays below root-only quarantine during construction. Sync/write or
SIGKILL failure preserves the partial root, not a ready bundle. A retry refuses
partial/unsafe material rather than fixing modes, replacing keys or deleting
history. A fully valid identical bundle is idempotent, including retained input;
source/journal/anchor stores are not reset or rotated. Read-only verification
never supplies missing records. Physical SD/cache/power-cut durability remains G6.

The optional `outcome-live-origin-registration/v2` adds `ai_socket_uid` to the
prior exact registration fields. It pins an existing private AI socket's owner
and protected namespace; capture/observer UIDs cannot be that AI UID. The normal
`0600` socket / `0700` AI directory stay private. Root validates core/AI paths;
the non-root signer validates public configuration and its authenticated root
parent without reading private AI/core directories. No ACL/group grant is used.
Registration v1 remains supported for its original root-owned-socket profile.
The enrollment helpers accept the explicit `--ai-socket-uid` option.

Live signers additionally refuse retained saved UID/GID, supplementary groups
or effective/permitted/ambient capabilities, then set Linux
[no-new-privileges](https://docs.kernel.org/userspace-api/no_new_privs.html)
before key use. This does not alter the core's existing provider capabilities.
Trusted root, signer-code/key and kernel/loader/dependency assumptions remain;
it is not isolation from root or a compromised capture UID.

## Reviewed single-unit transition

`service_switch plan` is read-only apart from fresh read-only witness RPCs and
safe isolated runtime/health probes. It refuses until all of these verify:

- complete bundle, matching keys/registration, supported native ABI and guard
  capability; complete signed source with a clean previous session (or empty);
- operator-installed root-protected Python/component code; **the original venv
  executable path is preserved**, and `python -I` imports that same installed
  component and preprovisioned crypto without caller PYTHONPATH fallback;
- fresh nonce-bound witness proof from the existing observer UID; exact current
  journal head and preservation of the protected source prefix; no new journal
  writer/anchor access, initialization or witness advance;
- host PID 1 is systemd, unified cgroup identity, fixed loaded stable unit,
  root-owned hashed fragments, actual main/core PID/start identity and no
  unmanaged or duplicate known core;
- existing unit/process is root, has the existing ability to drop UID/GID, no
  ambient/securebits surprise, and no unsupported user/root/path sandbox. A
  custom lifecycle hooks/unsupported unit types are also refused. A restricted
  or non-root unit is refused, **never elevated or relaxed**. Such
  profiles need separate commissioning rather than automatic extra privileges;
- registered and actual known core settings match, including TTL, polling,
  input/ledger/forwarding and enforcement. Boolean spelling can normalize;
  missing, removed or different settings are refused. Defaults of older
  software are not guessed. Only stdout is deliberately silenced for private
  capture. An inactive service cannot newly enable enforcement.

The plan includes a random review ID, exact code/configuration/process state,
trust digest and generated profile hash. Apply requires that concrete plan and
its exact expected SHA-256, rechecks before stopping, then records synced stages:

```
reviewed -> stop fixed unit -> verify stopped/cgroup/process absence
 -> hold shared core lease -> repeat proof -> publish full no-replace drop-in
 -> daemon-reload -> release lease -> start same unit
 -> verify one core + matching profile + new signed native start + live signer
 -> fresh protected witness/journal proof -> started receipt
```

The drop-in is
`/etc/systemd/system/azazel-edge-core.service.d/90-signed-input.conf`. Fully
written/fsynced private pending bytes are published with no-replace hard-link
semantics; another root administrator's existing drop-in is not overwritten.
A new native start race is arbitrated by the core lifetime lock. Manager calls
use fixed local systemctl/unit/arguments and a sanitized environment, without
remote bus/host environment overrides. No service is enabled by this tool.

The signed profile clears only ExecStart and sets the isolated verified service
entry. Every managed start (including boot/direct `systemctl start`) repeats
bundle/key/closed-history/runtime/native/fresh-witness checks before calling the
root launcher; it never initializes a witness, creates a replacement scope or
falls back when proof is missing. A failed pre-start leaves this optional unit
stopped. Commission witness startup/availability and an explicit ordinary-defense
recovery procedure before real activation. The running defense path is not
terminated by later observer/witness failure. The profile sets
`Restart=no`, `KillMode=mixed` and a bounded 90-second stop timeout. Per
[systemd's kill contract](https://github.com/systemd/systemd/blob/main/man/systemd.kill.xml),
TERM goes to the launcher so it can let core end/EOF/signing complete; final
KILL covers the cgroup. Other unsupported hardening is not silently removed.
Capture failure after launch still leaves the running defense core alone, as
in the existing live-origin contract. A valid old start without a live signer
cannot certify a healthy capture connection. A successful handoff is a
point-in-time process/provenance check, not future availability or telemetry
completeness. Observer intake still needs separate verified boundary recovery.

Any stale plan, missing proof, key/runtime/manager failure or stop/start identity
uncertainty refuses completion. Failure after stop can leave the service stopped
or its new profile staged: this deliberately requires explicit operator recovery,
not automatic unsigned fallback, reconnect, key regeneration or scope reset.
Receipts remain private for review. Replay of the same receipt/plan is refused.

`restore` requires the exact owned receipt and proven inactive/no-core state.
It removes only the unchanged managed profile (or recognizes our exact two-link
interrupted publication), reloads and **does not start a service**. Changed,
foreign or ambiguous configuration is not overwritten. No key/source/journal/
anchor is removed, and removing a profile does not repair an unclosed capture
scope. The operator may separately authorize ordinary defense startup after
review; any unsigned interval remains an observation gap.

## Explicit offline procedure

1. Prestage the reviewed target-ABI core and a dedicated root-owned installed
   capture Python/crypto environment from trusted offline artifacts. Prepare
   existing dedicated numeric accounts and root-protected core/state paths.
   Build/review the public v1 template and complete actual environment. Existing
   implicit/missing settings require separate explicit configuration review;
   the switch does not infer or change them. No dependency downloader is run.
2. Prepare public candidates against an absent bundle:

   ```sh
   python -I -m azazel_edge.outcome.input_service prepare \
     --bundle /var/lib/azazel-capture/scope01 --policy /secure/public-v1.json \
     --binary /usr/local/bin/azazel-edge-core --environment /secure/core-env.json
   ```

   Add `--ai-socket-uid` only with the verified actual AI UID. Save the returned
   `trust_policy` and exact canonical compact sorted `registration` dictionaries
   as protected root files (registration has no trailing newline); review them.
3. Import pre-existing separate raw keys explicitly:

   ```sh
   python -I -m azazel_edge.outcome.input_service provision \
     --bundle /var/lib/azazel-capture/scope01 --policy /secure/trust-live.json \
     --registration /secure/origin.json --producer-key /secure/producer.raw \
     --witness-key /secure/witness.raw
   ```

   Verification is the separate `verify --bundle ...` operation. Partial/unsafe
   roots require evidence-preserving review, not removal/retry to claim continuity.
4. Initialize the separate witness and observer against the new empty bundle
   using their existing explicit one-time flags and correct UIDs. Establish a
   protected journal/head before planning. Do not reinitialize a used scope.
   Old normalized logs and events during preparation are never re-signed.
5. Run `python -I -m azazel_edge.outcome.service_switch plan --bundle ...`.
   Review its public `plan` plus `sha256`; save **only the plan dictionary** in
   the root-owned plan file used below, preserving the returned expected digest.

   ```sh
   python -I -m azazel_edge.outcome.service_switch apply --bundle ... \
     --plan /secure/reviewed-plan.json --expect-sha256 REVIEWED_DIGEST
   ```

   The returned receipt identifies the concrete transaction. On failure inspect
   it and the actual manager/process state; never infer a completed transition.
   Use `restore --bundle ... --receipt ...` only for explicit inactive-profile
   recovery. There is no automatic start during restore.
6. Reopen observer intake only through its existing verified witness/journal
   loss/backlog/fresh-fence recovery. Lifecycle boundaries stop old windows;
   no downtime or later sample is substituted for missing evidence.

All commands above are operator procedures, not actions performed on a device
by this PR. New software/key registrations cannot mutate a used scope's pinned
history; image/key rotation and forensic scope transitions remain separate work.

## Test evidence and remaining gates

Tests use a network-disabled Linux container, read-only checkout, generated
synthetic temporary keys, actual root/capture/observer UIDs, real normal/signed
core processes and Unix witness, and actual isolated Python and systemd syntax
checks. A modeled manager injects state drift, sandbox/privilege/config mismatch,
stop/reload/start faults, publication interruption, duplicate operations and
explicit restore. This model is **not a real PID-1/systemd service stop/start**.
The native singleton, peer/key permission and fresh-proof paths are exercised
separately with real processes. No production files/accounts/services change.

Target-host systemd cgroup/stop/reboot/SELinux/AppArmor/capability/account integration,
artifact/dependency/permission commissioning, native workload/availability and
release readback on target, physical power cuts/storage/cache/wear and Pi
CPU/RSS/disk/latency remain #400/G6 gates. Root/key compromise, coordinated
whole-store rollback, trusted clocks/boot and external monotonic anchoring retain
the earlier limits. #393 retains independent service measurement. Keep #400 open;
software passes alone do not prove physical effect or comparative/causal benefit.

The earlier modeled-manager evidence remains separate from the new actual-PID1
VM checks. Service snapshots additionally require the local `/usr/bin/busctl`
typed lifecycle properties: `systemctl show` suppresses empty Exec arrays even
with `--all`; missing/unsupported D-Bus data is never inferred to be empty.
The opt-in witness CLI supports `--systemd-notify` for `Type=notify`, gracefully
closes its endpoint on TERM/INT and retires a dead socket only after acquiring
and validating the same protected store. Neither readiness nor transport cleanup
initializes/repairs evidence or permits unverified connected restarts.

### Exact mode for a newly created managed drop-in directory

The switch creates a missing managed directory privately (`0700` subject to the
operator's existing umask), opens that new owned directory with a no-follow
file descriptor, verifies its named/opened device and inode, then uses only
`fchmod` on that descriptor to reach exact `0755`. It verifies ownership, identity
and exact mode again, and syncs both the directory and protected parent before
publishing the managed file. The process umask is never changed.

Existing names are validated unchanged: an existing `0700`/otherwise wrong-mode
directory, symlink, non-directory or foreign owner is refused, never repaired or
replaced. A detected replacement or I/O failure retains the newly created state
for review; it does not delete or chmod the replacement. The root-owned protected
parent remains the trust boundary; this does not claim exclusion of a hostile
root or another trusted operator racing the namespace. No unit/permission/profile
or enforcement default changes follow from correcting this creation precondition.
