# Explicit v2 read-only telemetry composition

This is test-only composition code. No four-assignment v2 manifest or actual trial
is qualified by these helpers. The earlier single authenticated connection and
separate signature-refusal cases remain evidence at their own frozen source;
they do not admit a changed source or establish service efficacy.

`read_telemetry_assignment(manifest_sha256, start_head, *, source_commit,
archive_sha256, core_sha256, abi_sha256, interpreter_sha256)` reads the original
protected fixed guest layout only. The v2 preparation validator checks the
explicit five-field ticket, exact v2 manifest/mode, source/core and independent
external pins. Root must already have authenticated the entire source archive
outside this reader. A revision file, imported receipt or self-reported hash is
not source authentication. Legacy `planned`, `validate_manifest`, reader and
freshness public entrypoints remain closed to v1.

The reader shares the original signature, exact signed witness-prefix, journal
lifecycle, terminal cursor, complete callback, replay, service capture and clock
validators. Both C0 and throttle require the complete signed session and durable
terminal/witness closure. A baseline recording of `None` in measurement does not
waive that chain or transform its genuine native dry-run facts into application.
Original live Outcomes and their hashes remain retained separately from the
explicit read-only Root-probe-augmented G5 projection. Existing policy-source-label
comparison rules are unchanged; unsupported differences withhold calculation.

V2 additionally checks the retained initializer/live pre-API bundles against their
original READY bytes and both raw systemctl/typed busctl backends, including exact
argv, return code, stderr and typed empty hooks. Existing pure role, proc-view,
namespace-mount and three-FIFO validators are reused. Current protected source,
ABI and interpreter bytes must match the frozen pins. Public trust v4 and the
abstract socket cookie/boot descriptor remain separate from Root-owned namespace
device/inode metadata. Root role/listener/PID metadata is retained lab provenance,
**not** a signature binding the observer label or a fresh live-kernel attestation.
The reader opens no private key, store or endpoint and performs no NFT query,
actuation or lifecycle operation. The reused fixed VM guard only checks the
current environment; it does not create or start anything.

Before an active Root NFT query, the actual collector callback must already occur
in the original observed sidecar prefix. Full observed bytes, including a partial
tail, must exactly prefix the final closed sidecar. The complete prefix, original
row, hashes and recording UID/device/inode must match; no fake END, trimmed bad
complete row, reordered callback or backfilled epoch is accepted. The same fence
binds the final release callback before the absence query. Query launches and
actual query start/end clock anchors must follow those callbacks. Active query
completion must fit the existing two-second post-window and actual H5 horizon.

All six original Root query anchors contribute to the existing fixed 5ms sampled
clock budget, without fitting or shifting any epoch. They must lie within actual
controller start/end brackets. Baseline and controller start legitimately precede
live client launch; H0, active/absence queries, controller end, terminal closure
and actual helper return must fit the conservative 40s client-launch bound. The
service horizon stays five seconds and the client origin stays H0+1.25 seconds.
Both pre/post sample windows must fit H. Sampled consistency cannot prove clock
stability between samples. Missing, slow, drifted or ambiguous evidence withholds.

Original actor/namespace cleanup receipts must cover all seven fixed unit
families. Five clean client PID/argv pairs must exactly match the three query and
two peer launch receipts; all retained Root-child receipts must show clean reap
and group emptiness without forcing. Unknown, partial or failed evidence remains
withheld. No used state is retried, repaired, reset or reconstructed.

`validate_fresh_telemetry_records(manifest, read_results, *, core_sha256,
source_commit, archive_sha256, abi_sha256, interpreter_sha256)` accepts only the
unchanged actual reader returns in the trusted local workflow. It requires all
four exact assignment IDs, frozen order/configuration and unique boots, scopes,
sessions, registration hashes, run IDs and all eight producer/witness public
keys. It returns the original measurement-record objects in manifest order.
This is a local structural gate, not authentication of caller-authored JSON.

`read_telemetry_experiment(manifest, read_results, **pins)` applies that gate and
calls the existing `measure_experiment` unchanged only for a mechanical
diagnostic. Its outer result is always `status=withheld` with reason
`independent_safety_measurements_unavailable`. The diagnostic is retained under
`mechanical_diagnostic.calculation`; its numerical thresholds and ledger labels
cannot qualify benefit. All authorization/completion flags remain false.

The four `safety_violations` counts in this instrumentation path originate in
registration declarations, not independent category counters. Retained captures
and original historical artifacts stay unchanged; those counts are diagnostic
inputs, never measured absence of unauthorized action, protected escape, forged
evidence acceptance or advisory authority conversion. Each assignment now
explicitly labels its record `mechanical_diagnostic_only` and reports all four
safety observations as unknown (`null`). Caller booleans or JSON claiming safety
coverage cannot unlock the experiment API: no independent safety contract is
implemented. A future scope-bound observation contract requires separate review.

A per-assignment `calculation_available` is not measurement completion, runtime
authority, resume, production admission or permission to launch another scope. Broad interface and
system telemetry remains confounded; causal support and two-pair pilot limits
are unchanged. No new score, threshold or production entrypoint is introduced.

Synthetic tests exercise a complete four-record path with real ephemeral source
and witness signatures and unchanged public validators/calculation. Root/UID/file
ownership, role/kernel metadata, telemetry and clock sources are explicitly
synthetic. The collector uses `persistence=None`; journal bytes are manually
assembled through the existing fixture writer. These tests establish no actual
journal durability, systemd confinement, native execution or four-VM efficacy.

The complete four-assignment synthetic regression reaches the original
calculator's threshold gate with no integrity rejections, while the enclosing v2
API still withholds safety qualification. An attempted caller-supplied safety
flag is also ineffective. This is a software regression, not runtime safety or
efficacy evidence; existing clock/authentication/cleanup negatives remain strict.
