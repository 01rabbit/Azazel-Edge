core_sha256, abi_sha256, interpreter_sha256)` is an explicit Root function for a
**new VM/scope**, separate from every positive case. It has no CLI, four-run
manifest, H window, workload, G5 calculation, profile installation or activation.
Actual runtime remains gated on reviewed source and successful positive joined
API commissioning; this chunk has not run a VM case.

It uses current preflight and owned NamespaceSetup, externally staged profiles,
existing genuine witness-first provisioning and the current empty initializer.
The unchanged positive helper's fixed configuration/created-unit callbacks are
reused, including witness `-B`. The ordinary service unit may be freshly created
by provisioning, but this controller never starts it, invokes Switch, starts a
native producer, emits traffic or fabricates durable input_ready.

The fixed fault helpers retain the direct initializer context, empty source,
closed journal/zero cursor and witness anchors, then append one labelled synthetic
invalid-signature frame through the verified owned source FD. A fresh session ID
is generated for this owned negative fixture; no real signer/private key is used
for the fault. The file stays poisoned—no replacement, repair, rollback or retry.

The live helper independently collects and persists its actual pre-API proof,
rechecks current public/configuration bindings and releases GO. Its context body
only records owned role provenance. The helper retains original streams and
performs its own cleanup. The negative classifier accepts only the precise
signature refusal with unchanged source/journal/witness evidence, no API activity
or success artifacts and no helper cleanup errors. Generic failures, including
permissions, cannot qualify the case.

The classifier's own receipt remains explicitly **outer cleanup pending**. This
controller then independently attempts every owned fixed actor cleanup, witness
last, retains that proof and always attempts namespace/marker closure. Unknown
actor proof poisons namespace deletion; returned namespace cleanup must explicitly
verify success with no errors. Globals are restored after every path. Only clean
refusal plus complete outer cleanup permits `refusal-result.json`, whose scope is
one source-signature refusal and whose transition/experiment/admission/measurement
flags are false. It grants no general resume, label-cryptographic binding, service
effect or production acceptance.

Focused tests use real private source append/snapshot IO and the unchanged real
SourceVerifier/Ed25519 refusal. Setup, namespace, UID/LSM, genuine-initializer,
